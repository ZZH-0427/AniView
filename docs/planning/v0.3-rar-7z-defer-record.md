# RAR / 7z — product integration gate record

2026-11-05. M10C1 audit COMPLETE; fresh Android Edge and Quark feasibility passed.
This is a defer/gate record, **not** an approved M10C2 implementation plan.

The promising reference is sevenzip-wasm 26.5.0 (7-Zip 26.05). Existing ZIP and
password ZIP remain on zip.js 2.23.0 with no implementation changes. See the
[audit](../research/v0.3-rar-7z-feasibility-audit.md) and
[candidate matrix](../research/v0.3-rar-7z-candidate-matrix.md).

## Decision and rationale

Final audit outcome **TECHNICAL SPIKE REQUIRED**. Defer adding a production RAR/7z
dependency until the following gates pass. Desktop format support alone does not
establish a safe phone parser. Current prebuilt maximum WASM memory is 2 GiB;
output caps and main-thread deadlines do not stop earlier header/dictionary
allocations. CLI stdout is not a robust typed metadata API for hostile names.
License/source/replaceability arrangements have not received release approval.

## Required bounded-backend proof, if explicitly authorized later

1. Pin a maintained engine and reproducible compiler/source/patches. Demonstrate
   an enforceable total linear-memory ceiling; do not rely on an observer grow
   hook or a CLI option that covers only selected decoders. Compare structured
   library binding versus a carefully bounded read-only CLI adapter.
2. Bound metadata/header output before allocation/publication, dictionary memory,
   actual selected output and cumulative solid work. Reject links/unsafe paths,
   unsupported codecs/encryption and multi-volume/SFX. Prove typed errors and
   binary format whitelisting; do not turn generic exit code 2 into certainty
   about wrong passwords. Do not extract all files to MEMFS/OPFS.
3. Prove cancel/close → Worker termination → clean reopen, stale result isolation
   and no secret retention/logging. Treat archive-opening encrypted headers
   separately from ZIP entry prompts; keep the accepted ZIP session untouched.
4. Supply a concrete notices/corresponding-source/build/replacement distribution
   design. Evaluate LGPL-2.1-or-later/unRAR and component terms without changing
   AniView's UNLICENSED policy or asserting legal guarantees. A 7z-only whitelist
   does not remove RAR code/license from a combined binary.
5. Test small, measured medium and controlled larger cases on desktop and a
   bounded medium envelope on Android Edge/Quark. Choose production numbers only
   from those results, not ZIP's 512 MiB or theoretical WASM limits. Current
   experiment sizes are evidence points, not approved product caps.

Only after those gates should a product plan propose Option C: one small
UI-facing archive source contract, unchanged ZIP session, and a separate extended
session/Worker whose VirtualFiles feed the existing media pipeline. Consider
splitting 7z and RAR milestones only if actual build/license/capability evidence
supports that split. No production dependency/version is approved now.

Both current phone runs passed the isolated build's nine cases and one cancellation,
with 10/10 Workers and zero active Workers; max observed WASM memory was 17,039,360
bytes in each browser. This success cannot by itself close the hard-bound or
distribution gates above. RAR/7z are
optional V0.3 enhancements; deferring them does not block the stable Creator/ZIP
feature set or authorize another roadmap feature.

STOP. Further technical spike or product implementation requires a new task.
