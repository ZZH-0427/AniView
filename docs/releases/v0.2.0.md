# AniView v0.2.0

**Release package prepared; not yet released.** Publication requires explicit
approval and successful production validation. This is the prepared release body,
not a claim that the live site already serves V0.2.

## Highlights

- Create GIF animations from static JPEG, PNG and WebP images.
- Convert GIF, Animated WebP and APNG between their animated-image formats.
- Export animated images as H.264 MP4, and convert supported videos to animations.
- View static/animated images and browse local ZIP entries in the shared viewer.
- Use the interface in English or 简体中文, on desktop or supported mobile browsers.
- Keep media processing local, with cancellable jobs and bounded resources.

## New conversion features

**Create animation** accepts 2–200 static images, with ordering, removal, duration
and loop controls. It generates **GIF only**. Save/reopen that GIF to convert to
Animated WebP or APNG; direct multi-target image creation is deferred.

Animation conversion supports all six directions between GIF, Animated WebP and
APNG. Result Preview, Back and Download preserve the source workflow. Downloads
receive distinct names, including repeated downloads of the same result.

Animation → MP4 exports one cycle as lossy H.264, with no audio. Transparency is
composited onto white; odd dimensions receive white padding to even dimensions.

Video → animation accepts MP4/H.264 or WebM/VP9 profile 0, **8-bit SDR opaque video**.
Audio is ignored. Trim and available FPS/resolution presets determine the sample
plan; output does not upscale. Supported output formats are GIF, Animated WebP
and APNG. Equal consecutive frames may be merged in the output.

## Viewer and archive improvements

Playback, pause/resume, replay, frame inspection, Fit/1:1, zoom/pan and optional
fullscreen share the existing viewer. File navigation remains separate from frame
navigation. ZIP entries extract on demand and can enter animation conversion;
Back restores the original source/ZIP context.

## English / 简体中文

Switch languages without losing the active workspace, settings or result. A saved
choice overrides browser-language selection. Native video controls, pickers and
downloads use the browser/OS language. Ordinary pages omit engineering diagnostics.

## Stability and resource handling

Heavy processing uses Workers, bounded frame handoff and explicit cleanup. The
qualified RC passed 79 test files / 1,001 tests and desktop cross-feature checks;
real Android Edge and Quark RC workflows, downloads and final cleanup passed by
user report. No app-observable resource leaks were detected in the validated
flows. Native/GPU memory is not fully observable.

## Supported formats

| Format | Capabilities |
| --- | --- |
| JPEG/JPG, PNG, static WebP | View; static GIF-creator input |
| GIF, Animated WebP, APNG | View; inter-convert; H.264 MP4 export |
| MP4/H.264, WebM/VP9 profile 0 | Source preview when supported; animated-image output |
| ZIP | Browse supported image entries; normal viewer/conversion workflow |

## Known limitations

- Video needs a secure context and usable Worker WebCodecs/codec support. This
  release does not support every video format, profile or browser.
- GIF is palette-limited to 256 colors, binary alpha and centisecond timing; no
  dithering is applied. H.264 export is lossy, silent and one-cycle only.
- Video output: at most 150 sampled frames, 30 seconds selected, 720-pixel long
  side and 15,360,000 frame-pixels. Source/output each max 64 MiB. Decode-work
  guards may reject a file even when its selected output fits those limits.
- Animation conversion: at most 200 frames, 2,048-pixel sides, 4,194,304 pixels per
  frame, 15,360,000 frame-pixels and 64 MiB source/output; MP4 up to 30 seconds.
- Creator: 16 MiB combined input and the same per-frame/total frame-pixel limits;
  2–200 static images. Device memory and other archive/decoder limits still apply.
- Password-protected ZIP playback, RAR/7z, advanced editing, custom FPS/resolution,
  direct multi-target image creation and additional languages are deferred.
- Workspaces and results do not survive a full page reload. Download locations
  and whether files appear in the Android gallery depend on the browser/OS.
