## Known Limitations

- Creator direct output is GIF only, with GIF's palette/binary-alpha/timing limits.
- Password-protected ZIP playback is unsupported; encrypted entries are identified
  and can be skipped. RAR/7z are unsupported.
- Video input is limited to MP4/H.264 and WebM/VP9 profile 0, **8-bit SDR opaque
  video**. Audio is ignored. Video processing needs a secure context and usable
  Worker WebCodecs/browser/OS codec capabilities.
- Animation → MP4 is one cycle, silent, lossy H.264; transparent pixels are
  composited onto white. Odd dimensions receive white padding to even dimensions.
- Video → animation: at most **150 sampled frames**, **30 seconds selected** and
  **720-pixel output long side**, subject to frame-pixel/decode-work/deadline and
  other resource guards. Matching output dimensions alone does not guarantee
  that source decoding fits the workload limits.
- Existing image/archive/creator/conversion resource limits remain unchanged;
  available device memory may impose additional practical limits.
- A workspace and its media/results are not restored after a full page reload.
- Native/GPU memory is not fully observable. App-level cleanup evidence must not
  be described as proof of zero native/GPU memory leaks.
- Browser-native controls follow browser/OS language. Pickers, download locations,
  gallery indexing and optional fullscreen remain browser/OS-dependent.

## Deferred V0.3 Work

These are inherited **candidates**, not newly implemented or fully specified work:

1. **Priority 1 — Unified Multi-format Animation Creator:** direct static images
   → GIF / Animated WebP / APNG.
2. Password-protected ZIP.
3. RAR / 7z feasibility and possible support.
4. Advanced animation editing.
5. Custom FPS / resolution.
6. Additional languages.

Priority 1 direction: static images → canonical RGBA/static frame stream → target
encoder directly. The final direct-creation architecture must not use
images → GIF → decode GIF → WebP/APNG as its intermediate path, which would impose
GIF's 256-color and 1-bit-transparency losses before the final encoder.

Prefer reusing V0.2's GIF/WebP/APNG encoders, CanonicalFrameStream, Worker
backpressure, Preview, Download, result validation, resource guards and localization.
This records direction, priority and inherited capabilities only; interface design,
ownership decisions and the complete architecture audit belong to **M10A1**.
