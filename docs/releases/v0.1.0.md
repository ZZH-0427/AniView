# AniView v0.1.0

Release date: **2026-10-25**. The first public AniView release.
Final Android smoke passed in Edge and Quark by user report; validation evidence
is recorded in the [release QA](v0.1.0-qa.md).

## Overview

AniView is a local web viewer for animated and static images. Open an image or a
ZIP in a browser and inspect it without uploading media to an AniView backend.

**[Open AniView](https://zzh-0427.github.io/AniView/)**

## Highlights

- Animated WebP, APNG and GIF playback through a shared application-controlled pipeline.
- Play, pause, resume, replay and bounded-memory frame-by-frame inspection.
- Static JPEG, PNG and WebP viewing in the same responsive Canvas viewer.
- Multiple-file selection, desktop drag-and-drop and Previous/Next File navigation.
- Zoom, pan, Fit, actual size, touch gestures and fullscreen where supported.
- Local ZIP browsing with on-demand entry extraction.
- Compact icon controls, accessible names, keyboard operation and local processing.

## Supported Formats

| Kind | Formats |
| --- | --- |
| Animation | Animated WebP, APNG, GIF; single-frame GIF is also supported |
| Static images | JPEG/JPG, PNG, static WebP |
| Archive input | ZIP with supported image entries |

Animated playback uses AniView's own decoding and playback pipeline rather than
relying on browser-native animated `<img>` playback as its baseline. A system
picker may show additional image types; that does not make them supported.

## Viewer Features

Animations open paused on the first frame. Play starts or resumes playback;
Replay restarts and plays. Previous/Next Frame pause playback and stop at the
endpoints. Frame inspection keeps a bounded cache and can reconstruct older
frames instead of retaining every decoded frame.

File navigation is distinct from frame navigation. New files open in Fit;
changing animation frames preserves the current zoom and pan. Use 1:1 for one
image pixel per CSS pixel, zoom buttons or the mouse wheel, drag to pan, or
pinch and double-tap on touchscreens. Fullscreen is available when supported by
the browser. Static images omit animation controls.

The viewer provides button titles, accessible names, keyboard shortcuts and
phone-sized touch targets. More → Remove from list changes the temporary viewing
list without deleting the original device file.

## ZIP Support

Read ZIP metadata and browse image entries without manually extracting the
archive. Only the current entry is extracted, and opening a different source or
closing the archive releases the current session. ZIP loading is deferred until
the archive action is used.

Password-protected entries are identified and public sibling entries remain
navigable. **Password entry UI is not included.** Unsupported compression,
corrupted data and resource-limit failures have recoverable messages where
possible. RAR and 7z are unsupported. See [resource limits](v0.1.0-limits.md).

## Privacy

Images, decoded frames and ZIP contents are processed locally. AniView does not
require a backend upload or account, includes no analytics, and does not upload
media, passwords or diagnostic snapshots. The browser downloads application
assets from GitHub Pages. Optional `?debug=1` diagnostics are local, initially
collapsed and preserve the same safety limits.

Other browsers are outside this validation matrix. Fullscreen and the system
picker vary by browser/OS. Final Android smoke passed in both Android
browsers; the tested commit and results are tracked in the [QA record](v0.1.0-qa.md).

## Known Limitations

- Images are limited to 64 MiB encoded; static images to 4,194,304 pixels and
  16,384 pixels per edge. Display Canvas and archive limits also apply.
- Browser/device memory pressure can still prevent supported media from opening.
- No password-entry UI, RAR/7z, conversion, static-image-to-animation creation,
  video conversion or converted-file export.
- No timeline/arbitrary frame seeking or thumbnail gallery.
- HEIC, TIFF, AVIF, SVG and BMP are not supported formats.

These are the scope of this release. Resource limits mitigate hostile input;
they do not promise successful handling of every file or a fixed total browser
memory footprint.

## What's Next

Potential future work includes password ZIP UI, static images to animation,
GIF/WebP/APNG conversion, animated images to video, video to animated formats
and export workflows. These features are unavailable in v0.1.0 and have no
promised release date.
