Two final builds must compare paths/count/raw size/SHA256/gzip for every file,
including Workers/WASM/CSS/JS/notices/identity. Canonical manifest and actual source

runtime sources, dependency graph excluding only root version metadata, Workers,
archive/codec/security policy and distribution inputs. A test count alone is not
equivalence evidence. Only release identity/version text may change in runtime
assets; any unexpected product difference stops preparation.

A commit cannot embed its own SHA. The clean build checkpoint and later
preparation/evidence-only attestation are identified separately. After the last
attestation, rebuild and freeze the exact proposed HEAD again before approval;
compare both final manifests and all runtime bytes to the accepted RC. The final
preflight names that exact source SHA and canonical manifest hash. Subsequent
production evidence belongs on release/v0.3.0 after approval and verification;
do not silently substitute an older identity or recommit generated dist/.

## Failure handling

- Push timeout: read actual remote ref first; if accepted, do not create another
  commit or blindly retry. On incompatible remote history, stop; no force/reset.
- Pages failure: retain exact run/logs, do not tag/announce release. Diagnose and
  propose a forward repair; a changed candidate needs fresh verification/approval.
- Asset mismatch: report exact expected/actual path and SHA; never mark it PASS.
- Product failure: RELEASE DEPLOYED / PRODUCTION VERIFICATION FAILED; no RELEASED /
  VERIFIED claim. Preserve history; no tag movement or automatic destructive rollback.
- Tag/Release error: inspect exact remote tag/peeled commit and current Release;
  retry the correct operation without manufacturing a different tag or commit.
