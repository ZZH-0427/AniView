# AniView V0.3.0

## What's new

- Create **GIF, Animated WebP or APNG directly from static JPEG/PNG/WebP images**.
- Browse **password-protected ZIP**, including traditional ZipCrypto and
  WinZIP AES-128/192/256.
- Open supported **single-file RAR4, RAR5 and 7z** archives through a separate,
  bounded, read-only archive component.
- Keep the existing shared Viewer, conversion, Preview/Download and English /
  简体中文 workflows, with local processing and cancellable jobs.

## Multi-format animation Creator

Add 2–200 static images, append, reorder or remove sources, choose a shared frame
duration and loop count, then generate GIF, Animated WebP or APNG. Returning from
Preview preserves the source list, settings and result. Each Download request
receives a distinct filename.

All three encoders consume the same bounded canonical RGBA frame stream.
**Animated WebP and APNG do not pass through a GIF intermediate**, preserving
their direct access to source colors and partial alpha. GIF retains its
256-color palette, binary transparency, no dithering and centisecond timing.
Per-frame timeline editing and free-form resizing are outside this release.

## Archive formats

| Format | Supported workflow |
| --- | --- |
| Ordinary ZIP | Read metadata and extract the selected supported image on demand. |
| ZipCrypto; WinZIP AES-128/192/256 | Unlock accepted encrypted entries with a session-local password, then use the normal Viewer/conversion flow. |
| Single-file RAR4, RAR5 and 7z | Bounded listing and verified selected-entry extraction, including the validated password, encrypted-header and solid-archive cases. |

ZIP continues to use **@zip.js/zip.js 2.23.0**. RAR/7z uses a separate,
lazy-loaded SevenZip WASM Worker; opening Home or an ordinary ZIP does not load
that component. Passwords remain in the current archive session and are dropped
on archive close or replacement. Neither passwords nor media are uploaded.

The RAR/7z component caches at most one verified plaintext entry. Cancellation
terminates its Worker; reopen/retry creates a fresh session. Opening an archive
does not extract all of its contents. This is supported media browsing, rather
than a general archive-writing or extract-all workflow.

### RAR/7z processing boundary

These are simultaneous safety ceilings. A selected file can be small while the
work needed to reach it exceeds another limit.

| Guard | Limit |
| --- | ---: |
| Input archive | 15 MiB |
| Selected-entry output | 4 MiB |
| Recognized/declared dictionary | 4 MiB |
| Entries | 1,000 |
| Single path | 1,024 UTF-16 code units |
| Total path text | 131,072 UTF-16 code units (128 Ki units) |
| Cumulative source reads / maximum read chunk | 128 MiB / 1 MiB |
| Operation deadline | 15 seconds |
| WASM initial / compiled maximum memory | 16 MiB / 64 MiB |
| WASM mode | Nonshared; memory growth enabled |

Solid archives may require decoding preceding data. Dictionary/header preflight
recognizes only available metadata; the hard memory and work limits remain the
fallback. The 64 MiB limit bounds WASM linear memory, not the whole browser tab.

## Existing Viewer and conversion capabilities

- Static JPEG/PNG/WebP and application-controlled GIF/Animated WebP/APNG viewing,
  with playback, frame stepping, file navigation, zoom/pan, Fit/1:1 and optional
  fullscreen.
- All six conversion directions between GIF, Animated WebP and APNG.
- Animated image → MP4/H.264: one animation cycle, no audio, white alpha
  composition and even-dimension white padding where needed.
- Supported MP4/H.264 and WebM/VP9 profile 0 → GIF/WebP/APNG, with existing trim,
  FPS and long-side presets. Audio is ignored; equal sampled frames may merge.
- Preview, return and local Download of generated/conversion results, while
  preserving the source workflow. There is no new general original-file download
  or frame-export control.
- English and 简体中文, preserving the active workspace while changing language.

## Security and stability

The bounded archive engine uses **7-Zip 26.05 with selected 26.06 RAR3/InBuffer
security and error-handling changes**, plus RAR4 raw-filename validation before
NUL truncation can hide unsafe metadata. Valid RAR4 Unicode name structures remain
supported. It is built with Emscripten 6.0.13 and retains the compiled 64 MiB
nonshared memory ceiling.

The release candidate has automated, desktop and user-confirmed Android Edge /
Quark validation. The supplied Android Home diagnostics show balanced reported
resources and zero applicable active-resource/cleanup-error counters. The
[validation record](https://github.com/ZZH-0427/AniView/blob/6baea97390c998722ebef16c28126a65641fff38/docs/milestones/milestone-m10e-android-rc-validation.md) separates
user reports from automated evidence. The independent Linux native harness
passed all 20 error-propagation cases; its separately built test component is
distinct from the shipped Windows-built WASM. The
[native verification record](https://github.com/ZZH-0427/AniView/blob/6baea97390c998722ebef16c28126a65641fff38/docs/milestones/milestone-m10e-s2-native-security-backport.md)
preserves that scope and the earlier Windows tool-blocking history.

## Known limitations

- No multi-volume RAR/7z support, SFX compatibility guarantee, archive writing or
  automatic recursive archive browsing. Additional archive formats are excluded.
- Some encrypted failures cannot reliably distinguish an incorrect password from
  damaged data. Encrypted ZIP central directories and unsupported proprietary
  encryption/methods are outside the accepted set.
- Video support depends on codec/profile and browser/OS capabilities, in a secure
  context with usable Worker WebCodecs. Video input is 8-bit SDR opaque content;
  HDR/alpha video and audio conversion are excluded.
- H.264 MP4 output is lossy; transparency is composited onto white.
- Media lists, passwords and results are temporary session state. A full page
  reload does not restore the prior workspace.
- Browser/OS download handling controls where results appear. A saved file may
  be in Downloads without being indexed by the Android gallery.
- Processing ceilings remain unchanged: Creator uses at most 200 inputs, 16 MiB
  combined source, 2,048 pixels per output side and 15,360,000 total frame-pixels;
  output is at most 64 MiB. Animation conversion admits at most 200 frames and
  64 MiB source/output; MP4 duration is at most 30 seconds. Video→animation admits
  at most 150 sampled frames, a 720-pixel output long side and a 30-second selected
  interval, with additional decode-work guards. See the
  [README limit table](https://github.com/ZZH-0427/AniView/blob/6baea97390c998722ebef16c28126a65641fff38/README.md#processing-limits).
- Resource diagnostics measure application ownership. Full native/GPU/browser
  memory is not independently observable; supported files can still exceed a
  device's available resources.

## Local processing and privacy

AniView runs in the browser. Image/video bytes, archive contents, archive
passwords, decoded frames and generated results stay local. There is no media
upload backend, account system, analytics or diagnostic upload. The hosting site
supplies application assets; runtime media processing has no CDN dependency.
The UI language preference can persist locally; media is not stored there.
Optional local diagnostics do not increase the processing limits.
