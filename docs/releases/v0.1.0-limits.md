# AniView v0.1.0 resource limits

These are application safety limits, not a measurement of available device RAM.
They apply to the prepared v0.1.0 viewer. Browser/native/codec/Canvas allocations
can still fail under device memory pressure.

## Images and viewing

| Resource | Limit / behavior |
| --- | --- |
| Encoded image or extracted media entry | 64 MiB |
| Static image pixels | 4,194,304 |
| Static image edge | 16,384 pixels |
| Animated full RGBA frame admitted by the automatic player budget | 16 MiB / 4,194,304 pixels |
| Normal animation cache | 16 MiB, at most six frames |
| Large-frame automatic cache | Two frames when needed, at most 32 MiB |
| Display Canvas backing | 8,192 pixels per edge; 16,777,216 pixels total |
| Viewing list | 1,000 references |

Frame-by-frame inspection may reconstruct older frames. The frame cache does
not include encoded data, decoder workspace, native bitmaps, Canvas copies or
the browser's own memory. Animations remain subject to format/parser limits;
the separate WebP codec preflight is not an increase to player frame admission.

## ZIP

| Resource | Limit |
| --- | --- |
| Encoded archive | 512 MiB |
| Central-directory read/allocation | 16 MiB |
| Entries, including directories and hidden entries | 10,000 |
| Per-entry uncompressed data | 64 MiB |
| Total declared uncompressed data | 2 GiB |
| Declared compression ratio | 1,000:1 |
| Individual path | 1,024 UTF-16 code units |
| Cumulative path length | 2,097,152 UTF-16 code units |

Only the current image entry is extracted. The 2 GiB declaration guard does not
permit extracting all entries together. Integrity, compression method and path
checks also apply. Encrypted entries are identified, but v0.1.0 has no password
entry UI. These checks mitigate excessive workloads and are not a guarantee
against every malformed or malicious archive.

## Compatibility and recovery

The viewer needs Canvas 2D, Pointer Events, ResizeObserver, AbortController,
animation-frame scheduling and local File/Blob APIs. Animations and ZIP use
module Web Workers. Animated WebP requires WebAssembly; static images require
`createImageBitmap`; APNG requires Worker-side `createImageBitmap` and
OffscreenCanvas. GIF does not require OffscreenCanvas. Fullscreen is optional.

Oversized, unsupported or damaged inputs report a categorized error where
possible; a later supported file can still be opened. See the
[release QA record](v0.1.0-qa.md) for final candidate validation and the
[Milestone 6 record](../milestones/milestone-6-stability-compatibility.md) for
detailed policy, measurements and browser-specific evidence.
