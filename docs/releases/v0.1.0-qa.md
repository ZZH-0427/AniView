## Release identity

- Version: **0.1.0**, sourced from package.json and synchronized package-lock.json.
- Final release commit: the `commit` field in the generated
  [production build identity](https://zzh-0427.github.io/AniView/release-candidate.json).
- Branch: main. The final handoff records the full matching Git HEAD hash.
- `sourceDirty` must be false for the published build. A build from a source
  archive without Git records null and does not identify the release commit.
- The `release-candidate.json` filename is retained as a build-identity endpoint.
  The published product is version 0.1.0; this filename does not mark it as a prerelease.

Build identity is generated from package metadata and Git HEAD after the clean
Vite build. It contains no timestamp, local path, user filename or build number.
This keeps the final commit identity accurate without putting a self-referential
commit hash in a file whose edit would itself change that hash. The build report
also records production asset sizes; generated output is not committed.

## Production content policy

All 19 milestone-only files formerly under public/validation/ (661,341 bytes)
have moved to [repository validation fixtures](../../tests/fixtures/validation/).
No media/ZIP validation samples remain in the production public tree. Generators
and browser scenarios use the local corpus, including the same original encoded
media bytes. Historical milestone links now point to repository copies.

Normal startup does not select or fetch a fixture. ZIP code remains a lazy
dynamic import, and its Worker loads only when opening an archive. The public
tree contains the favicon and aggregated third-party notices. The build adds
HTML, application/lazy/Worker/CSS/WASM assets and the small build identity.
The earlier isolated WebP engineering harness remains lazy and is not loaded
or displayed in ordinary viewing.

The release build contains 14 files, about 706 kB total, and no validation assets.
Main application JS/CSS and all decoder/ZIP Worker/WASM hashes match the validated
7A build; no media runtime source changed. Both size measurements use Node
gzipSync with the same settings:

| Asset | Raw bytes | Gzip bytes |
| --- | ---: | ---: |
| Main JS | 288,764 | 87,482 |
| Main CSS | 10,163 | 2,885 |
| WebP WASM | 138,564 | 49,736 |
| ZIP Worker | 139,317 | 61,639 |
| ZIP session lazy chunk | 6,577 | 2,281 |
| APNG / GIF / WebP Workers | 21,426 / 13,043 / 24,735 | 7,378 / 5,229 / 9,222 |
| Lazy engineering page JS / CSS | 4,881 / 667 | 1,806 / 354 |
| Third-party notices | 56,901 | 12,012 |

The 39,293-byte notice increase accompanies the removed 661,341-byte validation
tree. Notices are a separate static text resource and do not grow the runtime
JS/CSS bundles. The build identity is a small generated JSON file whose
length can vary with the metadata values.

## Regression and cleanup

Final checks cover Animated WebP, APNG, GIF, JPEG, PNG, static WebP, ZIP,
Play/Pause/Replay and looping, frame stepping, zoom/pan, fullscreen when available,
file navigation, More, input/drag-and-drop and MediaSession. Normal mode must
render no diagnostic UI; debug panels and Raw JSON must start collapsed.

Closing an animation, a static file and an archive must leave zero active
Workers, static bitmaps and archive sessions. Desktop instrumentation checks
ownership and response paths without uploading the chosen media. Detailed
stress/soak and device limitations remain in the
[Milestone 6 record](../milestones/milestone-6-stability-compatibility.md).
This preparation does not repeat the full extended soak unless a blocker
requires a relevant runtime change.

The final local Edge Viewer run closed 18/18 Workers and 29/29 static bitmaps,
with zero remaining active resources. Its 5,809 RGBA transfers detached correctly;
1,497 APNG emissions peaked at one temporary bitmap with zero after emission.
Input/drag-and-drop closed 25/25 Workers, including cancellation, duplicate
selection, 1,000-item limits, non-file drops and recovery checks. Chrome core
closed 10/10 Workers and 11/11 static bitmaps; UI normal/debug page resource
counts balanced independently. No page exception, unexpected console error or
runtime asset 404 was observed by these harnesses.
