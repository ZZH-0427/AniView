# AniView V0.3 — scope freeze

Date: 2026-11-11. **Functional scope frozen for M10D. V0.3 remains IN DEVELOPMENT.**

This freeze is based on the cumulative implementation at `d831a87` and the closed
M10A/M10B/M10C records, checked against current source. M10D makes only the approved
production-entry and documentation cleanup. It does not start M10E, identify a
release candidate, merge main, bump the current package version `0.2.0`, create a
tag or publish V0.3. Main and the v0.2.0 release remain frozen.

## Included capabilities

| Area | Frozen scope |
| --- | --- |
| Viewer | JPEG, PNG and static WebP; GIF, Animated WebP and APNG. Existing controlled Canvas animation playback, pause/replay/frame stepping, file navigation, zoom/pan/Fit/1:1 and capability-dependent fullscreen. |
| Animation Creator | Ordered static JPEG/PNG/WebP inputs directly produce GIF, Animated WebP or APNG, with existing add/reorder/remove, global duration and loop settings, result Preview/return and Download. |
| Animation conversion | GIF→WebP/APNG, WebP→GIF/APNG and APNG→GIF/WebP; animation→MP4/H.264; MP4/H.264 and WebM/VP9→GIF/WebP/APNG within the accepted codec/profile and workload gates. |
| Archives | Ordinary ZIP; traditional ZipCrypto and WinZIP AES-128/192/256; bounded single-file RAR4, RAR5 and 7z browsing, supported media access, validated passwords/encrypted filenames and supported solid archives. |
| Localization | English and Simplified Chinese, with existing locale switching and settings preservation. |

Preview and Download above mean the existing generated/conversion-result flows.
They do not add a general original-file download control, frame export, or a new
Viewer editing/export workflow. Browser download location/gallery indexing stays
browser/OS controlled.

### Shared processing boundaries

The existing `VirtualFile` input and media/Player/Renderer boundaries remain.
Creator uses `StaticImageSequenceSource` → canonical full-canvas RGBA frame stream
→ the selected existing encoder Worker, with transfer/accept/ACK backpressure.
Direct WebP and APNG creation never pass through a GIF intermediate. It does not
retain all decoded source frames. The source scan, orientation and centered
composition policy is unchanged; creation does not add scaling or cropping.

Animation conversion reuses the canonical source/encoder stream. GIF's palette
and binary transparency limitations remain; WebP may merge identical consecutive
frames while preserving their timeline. APNG requires Worker deflate capability.
Video paths require the existing secure-context/WebCodecs/browser codec gates;
they do not promise every MP4/WebM codec, HDR/alpha video, audio conversion, or
availability on every browser. Animation→MP4 keeps the accepted single visual
timeline, white alpha composition, even-dimension padding and no audio.

### RAR / 7z narrow product boundary

The separate lazy SevenZip Worker remains independent of ZIP/password ZIP. It
holds one archive session and at most one verified selected-entry Blob; it does
not extract all entries. Cancellation terminates the synchronous native Worker
and permits explicit reopen/retry. Passwords stay session-local, with the existing
ambiguous password-or-corruption outcomes where the backend cannot distinguish.

| Guard | Frozen value |
| --- | ---: |
| Input archive | 15 MiB |
| Actual selected-entry output | 4 MiB |
| Recognized/declared dictionary | 4 MiB |
| Entry count | 1,000 |
| Single path | 1,024 UTF-16 code units |
| Cumulative paths | 131,072 UTF-16 code units |
| Cumulative source reads / maximum chunk | 128 MiB / 1 MiB |
| Operation deadline | 15 seconds |
| WASM initial / compiled maximum | 16 MiB / 64 MiB |
| WASM mode | Nonshared; memory growth enabled |

[EXTENDED_LIMITS](../../src/archive/extended/policy.ts) is the source of these
values. Dictionary preflight recognizes only available metadata/methods; it does
not guarantee rejection of every allocation before native parsing. The compiled
64 MiB bound covers WASM linear memory, not total JavaScript/browser/native/GPU or
device memory. Solid extraction may process preceding data and hit read, memory
or time limits even when the selected output is small. No arbitrary RAR/7z
method/archive compatibility guarantee is added.

Pinned engine 7-Zip 26.05 / Emscripten 6.0.13, native RAR4 raw-filename NUL/Unicode
validation, existing error mapping and source/patch/notices distribution remain
unchanged. Keep [component manifest](../../public/vendor/sevenzip/manifest.json),
[source/replacement instructions](../../public/vendor/sevenzip/README.md) and
the corresponding-source archive together. Component licensing does not select
a license for AniView itself.

## Existing controls versus deferred enhancements

Video conversion already has Start/End trim controls, target-specific FPS choices
and long-side presets. GIF offers 5/10/20 FPS; WebP/APNG offer 5/10/15/20/24/30.
Output presets are 360/480/720 or Original; Original still has to satisfy the
720-pixel output ceiling. These existing controls remain in scope; further
free-form FPS, arbitrary resolution and broader editing controls are deferred.
See [settings](../../src/video-conversion/settings.ts),
[output sizing](../../src/video-source/sampling-plan.ts) and
[current UI](../../src/video-conversion/ConvertVideo.tsx).

Explicitly deferred beyond this freeze:

- Advanced animation editing and a per-frame editing/timeline UI.
- Further custom FPS/resolution controls beyond the existing basic controls.
- Additional languages.
- Multi-volume RAR/7z.
- Additional archive formats.
- Guaranteed SFX compatibility.
- Automatic recursive archive browsing/extraction.

Encrypted ZIP central directories, PKWARE strong/proprietary ZIP encryption and
unsupported archive methods remain outside the accepted support set. No backend,
media/password upload, persistent media store or telemetry is introduced.
