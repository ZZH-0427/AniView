## Current Creator pipeline

Actual code path:

```text
src/pages/Home/Home.tsx: Create animation (create-gif-entry)
  → src/app/App.tsx: creating in-memory state; lazy CreatorWorkspace
  → src/creation/CreatorWorkspace.tsx: one owned CreationSession
  → src/pages/CreateGif/CreateGif.tsx: image/* multiple picker / file-only drop
  → src/input/file-input.ts / drag-drop.ts → browserFile → VirtualFile[]
  → CreationSession.add → detectCreationSource → BinaryFormatDetector
      ordered {id, file, format}; no decoded source cache
  → generate → StaticGifEncoder.encode(files, GIF options, product limits)
  → src/creation/gif/encoder.worker.ts (one dedicated Worker)
      read(index) → main file.read() → source ArrayBuffer transferred to Worker
      scan every source → identify → native bitmap decode → oriented dimensions
      close each bitmap; keep dimensions only
      max width × max height → guard → one OffscreenCanvas
      second sequential pass: decode → clear/draw centered → close bitmap
      → one ImageData.data RGBA → quantizeGifFrame → GifencWriter.write
      → finish → transfer capacity buffer + exact byteLength
  → CreationSession: Blob(image/gif), object URL, settings/encoder metadata
  ├→ real download anchor, fresh filename per activation
  └→ Blob-backed VirtualFile → existing Viewer/decoder/Player/Renderer
       Close → joined Viewer teardown → same Creator/result
```

Source admission reads a temporary prefix up to 64 KiB, with authoritative
out-of-prefix PNG chunk-header reads. It does not fully decode images or cache
encoded prefixes in the session. GIF/APNG/animated WebP are rejected, even with
misleading extensions. Adding sources does not inspect every oriented dimension;
the Worker performs that scan during Generate.

### Preparation and composition

[`runEncoding`](../../src/creation/gif/encoder-core.ts) runs in the Worker. It
requires Worker `createImageBitmap` and `OffscreenCanvas`. Each source undergoes
binary/dimension safety checks before native decode; bitmap decode requests
`imageOrientation: 'from-image'`. Two sequential native decode passes are used,
not header-only oriented-size inference. Metadata stores O(source count) sizes.

Output width is the **independent maximum oriented width**; height is the independent
maximum oriented height. These maxima can come from different sources. Each frame
clears the full canvas to transparent, draws at
`floor((canvasWidth-sourceWidth)/2), floor((canvasHeight-sourceHeight)/2)`, with no
scale/crop. Odd leftover padding goes right/bottom. A bitmap is closed before
`getImageData`. The whole-canvas RGBA is a Worker temporary, not session state.

## Current CreationSession

[`creation-session.ts`](../../src/creation/creation-session.ts) owns ordered source
handles, settings, admission/rejection messages, status/progress, generation ID,
AbortController, serialized adding/cancellation, asynchronous source releases,
one last successful Blob/URL and download namer. The workspace owns this lifetime;
MediaSession never acquires Creator source handles. Duplicate handles are allowed
and release only after the last duplicate is removed.

Edits/add/move/remove/settings are blocked while busy. Clear removes sources and
result but preserves settings. Settings/order/source edits retain the previous
result. New generation also retains it until a new success; failure/cancel retains
it. Success publishes the new result then revokes the old URL. Clear/dispose revoke
the result; dispose is idempotent and joins source releases. Generation checks
discard late progress/results. StrictMode replay is protected in CreatorWorkspace.

`cancel()` increments generation, aborts, joins the encoding service's cancellation
and publishes cancelled. The encoder serializes outstanding unabortable reads
across generations using `readGate`; it does not take source ownership. Its 30 s
inactivity watchdog and cooperative cancellation / 100 ms terminate fallback are
separate from source I/O cancellation. A provider read itself has no guaranteed
abort contract; prompt Worker cleanup does not prove that native read has ended.

### Result validation gap

Current Creator **does not perform independent decode-back before success**.
StaticGifEncoder checks result buffer/range/64 MiB, and CreationSession trusts
encoder metrics for dimensions/count and copied settings for timing/loops. There
is no `verifying` status. Real decoding happens only if Preview is opened or an
external test decodes output. Session tests deliberately accept a six-byte GIF
signature mock, confirming this distinction. M10A2 must add the existing 8B-style
actual output inspection for all three targets, including GIF, before success/URL.

## Current canonical pipeline and exact contracts

There is **no interface named `CanonicalFrameStream`** in this implementation.
The actual reusable contract is [`AnimationFrameSource`](../../src/conversion/model.ts):

```ts
interface CanonicalAnimationMetadata {
  readonly width: number; readonly height: number;
  readonly frameCount: number; readonly playCount: number;
}
interface CanonicalAnimationFrame {
  readonly index: number; readonly durationMs: number; readonly rgba: ArrayBuffer;
}
interface AnimationFrameSource {
  readonly metadata: CanonicalAnimationMetadata;
  readonly metrics: SourceMetrics;
  next(): Promise<CanonicalAnimationFrame | null>;
  acknowledgeFrame(): void;
  reset(): Promise<void>;
  close(): Promise<void>;
}
```

`SourceMetrics` records decodeMs, decoderHeapBytes, decoderBackupBytes and optional
directRgbaFrames/canvasReadbackFrames; these are not native/GPU memory measurements.
RGBA is full-canvas, fully composed RGBA8; byte length must be width×height×4.
Index is sequential from zero. Canonical duration accepts finite 0–655350 ms;
metadata validates integer dimensions/count/plays under CONVERSION_LIMITS.
`playCount=0` means infinite, `1` once, positive N total complete plays.

[`openAnimationFrameSource`](../../src/conversion/frame-source.ts) uses existing
GIFDecoder, WebPDecoder or APNGDecoder({canonicalRGBA:true}) transports. It borrows
the VirtualFile, bypassing Viewer ImageData/cache/Player. `next()` refuses overlap
or a held unacknowledged buffer. `acknowledgeFrame()` requires that handed-out
buffer has been detached. `reset` requires no outstanding frame; end is null after
the declared count. Close is idempotent, joining normal close or terminating busy/
aborted transports. Unsupported/read/decode/Worker/limit errors are normalized.

[`convertFrameSource`](../../src/conversion/convert.ts) pulls one frame, validates,
passes the **same buffer** to EncoderWorkerClient, awaits `accepted`, checks
byteLength zero, acknowledges source, then pulls again. It never draws or copies
RGBA. One canonical frame is in flight, without prefetch. In `finally` it disposes
encoder and closes source. Abort does both; ConversionJob has latest-generation
isolation. Raw returned metadata describes the **input**, not independently decoded
output. The function still takes one `VirtualFile` and applies its size limit;
it is not a ready-made ordered-multiple-static-files entry point.

### Worker protocol

[`conversion/protocol.ts`](../../src/conversion/protocol.ts): request
`open(target,metadata)` → `ready(capabilities.deflate)`; `frame(frame)` →
`accepted(metrics)`; `finish` → `result(EncoderResult)`; `close` → `closed`, or typed
`error`. Commands have request IDs. EncoderWorkerClient permits one pending request,
transfers `[frame.rgba]`, rejects a non-detaching transport, ignores stale IDs and
uses a 120 s command timer. Disposal terminates the Worker and rejects pending work.
There is no cooperative `cancel` message in this encoder protocol; abort/dispose
is the cancellation mechanism. Do not confuse it with the legacy GIF protocol.

| Property | Current static Creator | Canonical contract | Verdict/action |
| --- | --- | --- | --- |
| Width/height | Max oriented width/height, after Worker scan | One fixed metadata canvas | Compatible values; expose scan metadata |
| RGBA | ImageData.data inside legacy GIF Worker | Transferable full-canvas ArrayBuffer | Adapter required; bypass quantization |
| Duration | Uniform 20–10000 ms, normalized to 10 ms | Per-frame durationMs | Populate uniform value on every frame |
| Index | Source array iteration i | Frame index 0..N−1 | Directly compatible |

| Ownership | Worker temporary; quantizer mutates it | Ownership transfers to target | Adapter must transfer, hold detached handle until ACK |
| Transferability | Encoded source/output transferred, RGBA stays Worker-local | Source → broker → encoder RGBA transfer | New source Worker protocol/client needed |
| Cleanup | Legacy Worker closes bitmap/shrinks canvas/terminates | close/reset plus encoder dispose | New adapter implements equivalent cleanup/guards |
| Metrics | EncodeMetrics combines decode/quantize/write | SourceMetrics + EncoderMetrics | Composition wrapper, not invented zero timings |

**Overall: ADAPTER REQUIRED; not incompatible, not a direct type cast.**
No GIF byte stream or GIF decoder is needed to prepare a static canonical frame.

## Existing encoders and duplicate GIF entry paths

| Target | Current implementation | Accepted input / actual behavior |
| --- | --- | --- |
| Creator GIF path A | creation/gif/encoder.worker.ts → runEncoding → GifencWriter | Encoded static files, scan/composition and encoding in one Worker |
| Canonical GIF path B | conversion/encoder.worker.ts → GIFAnimationEncoder | Canonical frames, per-frame timing; no static decode/composition |
| Canonical WebP | conversion/webp-encoder.ts → existing WASM bridge | Canonical frames copied into one reusable WASM picture |
| Canonical APNG | conversion/apng-encoder.ts | Canonical full frames streamed to native deflate |

A and B are **different Workers/clients/wrappers**, not the same entry. Both use
gifenc@1.0.3 and **the same `quantizeGifFrame`** in
[`gifenc-adapter.ts`](../../src/creation/gif/gifenc-adapter.ts). GIFEncoder writer
setup/timing/loop/output guards have separate wrappers; canonical validation is
separate from static product/spike admission. No new quantizer/LZW implementation
is needed. Do not automatically merge/remove historical paths in M10A1.

Path B creates 256 entries at most, reserving index zero even for opaque images
(at most 255 opaque palette entries), mutates RGB beneath discarded alpha in place,
uses threshold <=127 transparent, RGB565 quantization, no dithering, disposal 2
and per-frame palettes. It shares these visible GIF policies with path A.

### WebP

[`webp-encoder.ts`](../../src/conversion/webp-encoder.ts) and
[`aniview_webp_bridge.c`](../../tools/webp-wasm/bridge/aniview_webp_bridge.c)
set lossless=1, exact=1, method=0, allow_mixed=0. RGBA copies once into a reusable
picture; C swaps RGBA to native ARGB in place. Full alpha is accepted; native
compressed-frame/workspace allocations are additional to the one-frame broker.
Adjacent identical visuals may merge. Existing PreserveSingleVisualFrame wraps a
static VP8L payload with animation headers to retain duration/plays. Output can
have fewer physical frames than sources while preserving the timeline.

Lossless here is relative to **prepared canonical pixels**. Browser image decode,
orientation/color management and Canvas premultiplication/unpremultiplication can
already differ from original stored PNG pixels/hidden RGB. Do not promise original
container metadata or all original hidden RGB survives native preparation.

### APNG

[`apng-encoder.ts`](../../src/conversion/apng-encoder.ts) writes PNG RGBA8,
noninterlaced, full-canvas fcTL SOURCE/NONE, filter byte 0, per-frame zlib via
Worker CompressionStream('deflate'), IDAT then fdAT with sequence numbers/CRC.
Writer and tests preserve canonical RGBA/alpha, including hidden RGB. It drains
compression concurrently with writes; scanlines view the current buffer and
one-byte filter scratch, rather than another full filtered-frame array. Missing
deflate returns TARGET_ENCODER_UNSUPPORTED; there is no fallback dependency.
Its independent inflation/CRC tests are stronger byte oracles than Canvas readback.

## Timing and loop semantics

Creator default **500 ms**, min **20**, max **10000**, ms units; both UI commit and
normalizeCreationSettings round nearest 10 ms (27 → 30). UI Play count defaults
1; Loop forever defaults true. Finite counts are integer 1–100.

| Canonical total plays | GIF writer repeat | WebP loop_count | APNG num_plays |
| ---: | --- | ---: | ---: |
| 0 infinite | 0 | 0 | 0 |
| 1 once | -1, omit extension | 1 | 1 |
| N finite | N−1 | N | N |

| Target | Encoder timing | Creator integration policy |
| --- | --- | --- |
| GIF | round(durationMs/10)×10; decoder maps encoded <20 ms to 100 ms | Keep 20–10000 / 10 ms product policy; avoids short-delay branch |
| WebP | round cumulative timestamps, including final end; duration is successive difference | Same global product value initially; integer multiples of 10 remain exact |
| APNG | Reduced durationMs/1000 fraction when fitting; bounded nearest fraction otherwise | Same global product value is exactly representable |

Maximum Creator timeline is 200×10000 = 2,000,000 ms, below existing WebP timestamp
and single-visual-frame wrapper limits. No new per-frame duration editor or custom
FPS feature is proposed. Keep current 10 ms setting normalization across targets
for initial M10A2 compatibility; making WebP/APNG controls 1 ms is a separate UX
change, not required to avoid GIF pixel/alpha loss.

All limits apply together, before allocations where practical.

| Limit | Existing product Creator | Canonical encoders | Proposed initial unified Creator |
| --- | ---: | ---: | ---: |
| Sources | 2–200 static files | Not a multi-source admission API | 2–200 |
| Input frame count | source count | 1–200 | 2–200; output WebP may merge to 1 |
| Side | 2048 | 2048 | 2048 |
| Pixels/frame | 4,194,304 | 4,194,304 | 4,194,304 |
| Canvas pixels × input count | 15,360,000 | 15,360,000 | 15,360,000, including duplicates |
| Aggregate encoded sources | 16 MiB | 64 MiB for one conversion VirtualFile | **16 MiB**, never relax to 64 |
| Per-source encoded bytes | 64 MiB lower-level guard; aggregate makes effective max <=16 MiB | Not a static admission policy | Preserve both; aggregate remains stricter |
| Output bytes | 64 MiB core/client checks | 64 MiB | 64 MiB |
| Settings | 20–10000 ms, 10 ms steps; 1–100 finite plays | duration 0–655350; total plays 0–65535 | Preserve stricter product policy |

Source dimensions are also validated by static metadata guards before native
decode and combined **oriented** canvas/workload checks before Canvas/encoding.
Keep detailed source/canvas/workload errors. SPIKE_ENCODER_LIMITS (10,000 etc.)
are historical harness ceilings and must never become product defaults.

GIF output guard is checked after synchronous writes, and WebP output size after
final assembly; these do not prevent every temporary overshoot allocation. The
canonical GIF wrapper does not repeat its cap check after finish appends the trailer;
the new creation service must independently validate the final exact range/cap,
as the legacy Creator client already does. APNG's
GrowingByteWriter bounds app-owned capacity before appending. 64 MiB is not a
guarantee of total browser memory. Do not raise any limit to make three targets fit.

## Resource ownership and target topology

| Resource | Current owner / creation | Current release | Proposed rule |
| --- | --- | --- | --- |
| VirtualFile | CreationSession owns ordered handles; reads main-side | Last duplicate removal, clear/dispose, joining releases | Preserve ownership; adapter borrows only |
| Encoded read buffer | main file.read, one cross-job gate; transferred | Detach on post, stale result dropped | Preserve cross-generation gate; no all-source byte cache |
| ImageBitmap | legacy Worker, sequential native decode, one live | close in finally, including late native decode | New source Worker keeps same location/lifetime |
| OffscreenCanvas | legacy Worker, one max-size backing | shrink to 1×1 in finally / Worker termination | One preparation canvas; no main-thread pixel processing |
| ImageData/RGBA | Worker iteration, bitmap already closed | Scope ends; quantizer mutates, no history | Transfer its buffer; drop view; no next frame until encoder ACK |
| Encoder workspace | GIF indexed/palette/output; WebP WASM or APNG deflate for canonical path | dispose/termination | Additional to canonical frame count; no zero-memory claim |
| Worker | service/client tracks each instance | normal completion/error/cancel/dispose | Explicit join/terminate for source, encoder and later inspection |
| Blob / URL | Session owns latest successful output/one URL | replacement success, clear/dispose | URL only after validation; Preview borrows Blob |

Recommended generation topology: **source preparation Worker → main transfer broker
→ existing canonical encoder Worker**. This preserves off-main sequential source
preparation but **changes Worker count from legacy one to two**. It is an explicit
medium-risk integration tradeoff for reusing the validated target Worker contract,
not a claim that topology/cost is unchanged. Co-locating three new target dispatch
paths inside the old GIF Worker would preserve one Worker but duplicate validated
transport/finalization behavior. No pixel preparation moves to main.

One full canonical RGBA buffer is logically in flight: source transfer → main
transfer → target acceptance → source ACK → next. Canvas backing, bitmap during
decode, the encoder's fixed picture/workspaces and compressed output remain extra.
The ACK is after acceptance, not merely postMessage. Inspection is a later pass,
after encoding/source teardown; do not overlap generation, readback and Preview.

## Result, Preview and Download reuse

Current CreationResult has Blob/URL/filename, GIF EncodeMetrics and metadata that
mixes UI settings with encoder dimensions/count/bytes. It has no format field or
actual duration. Current infinite UI settings keep playCount=1 with loopForever=true;
canonical infinite is 0. **Do not intersect these two playCount meanings in one
metadata object.** Keep immutable job settings separately from inspected metadata.

Existing `ConversionProductResult` in conversion-session.ts has an animation arm:
format: ConversionFormat, Blob/URL/filename, ConversionMetadata and EncoderMetrics.
The separate MP4 arm is not a Creator target. Reuse the animation arm **type-only**
(`Extract<ConversionProductResult, {format: ConversionFormat}>`), narrowing actual
Creator duration to number and enriching with captured settings/inputFrameCount/
source metrics. Do not import ConversionSession runtime or move its video model
just to rename types. CreationResult/CreationSession remain useful existing names.

`inspectConversionOutput` already performs a real decode-back, transferring one
decoded output frame to inspection.worker.ts, awaiting ACK and summing durations.
It returns actual dimensions, frame count, total plays and duration; it is not a
pixel-fidelity comparison. ConversionSession also binary-detects target animation
and checks dimensions/plays, count policy and total timeline tolerance <=1 ms.
Reuse those policies for Creator, including 1..inputCount physical frames for WebP;
do not present raw encoder metadata as output metadata or reject valid merges.

Existing Viewer supports GIF/WebP/APNG and Preview teardown/focus/scroll-return
already works. Only CreatorWorkspace's hardcoded `.gif` / image/gif VirtualFile
must become actual result filename/type. Preview creates no second result URL.
Extensions/MIME: gif/image/gif, webp/image/webp, png/image/png for APNG.

Keep the creator's neutral `aniview-animation-<time>-<nonce>-<counter>` stem and
generalize its extension factory. Every actual activation gets a fresh name;
old filenames/results are not overwritten and gallery indexing is not promised.
An old result retained after target/settings changes must use **its own format**,
including downloads while another generation runs, never the newly selected target.

## Lazy loading and bundle risk

App.lazy loads CreatorWorkspace. Constructing StaticGifEncoder does not create a
Worker; Generate does. Home loads no creator encoder Worker. Existing shared
conversion Worker selects targets with dynamic imports in source, but the accepted
Vite artifact **physically inlines all three encoder cores into one Worker**.
APNG therefore has no independent target JS fetch in that build. WebP WASM fetch/
instantiation occurs only when the WebP encoder is created (or a WebP decode is
actually needed). Do not confuse logical dynamic import with physical code splitting.

Inherited RC/release manifest measurements, not a new build:

| Artifact | Bytes / gzip |
| --- | ---: |
| Ordinary main JS | 284,481 / 85,789 |
| Creator lazy JS | 28,744 / 8,689 |
| Creator CSS | 6,122 / 1,745 |
| Legacy Creator GIF Worker | 24,191 / 9,240 |
| Shared-target encoder Worker | 45,991 / 16,013 |
| Existing WebP WASM | 394,132 / 159,999 |

The known encoder-Worker payload difference is +21,800 raw / +6,773 gzip, **not**
the total V0.3 delta: the new static-source Worker/client adds unmeasured code,
and chunks may be regrouped. Creator UI will grow for controls/adaptation; exact
size is unknown until M10A2 builds. Ordinary startup should gain no heavy encoder
imports, Workers or WASM. A tiny optional cleanup snapshot subscriber could add a
small entry delta; measure it, do not promise exactly zero bytes. Creating/opening
Creator must not instantiate target Workers; Generate creates only the source and
selected target instance. Keep current shared physical Worker for minimum risk;
independent target splitting is not required and is not a build-config task here.

Existing encoders suffice: **new dependencies = 0**; no WASM rebuild, new compression
implementation or new third-party licensing surface is planned. Existing notices,
libwebp/gifenc terms and UNLICENSED policy remain. This is a reuse assessment, not
a newly executed dependency or license audit.

## Architecture options and recommendation

| Option | Benefits | Costs / risks / test impact | Verdict |
| --- | --- | --- | --- |
| A — extend existing CreationSession | Preserve admission, sources/settings, workspace/URLs and latest-job semantics; replace only encoding boundary; reuse EncoderWorkerClient/cores | Medium localized diff: source Worker adapter, small static broker, verifying state and generic result/UI. Two Workers instead of one; mandatory legacy GIF parity and cancellation tests | **RECOMMENDED** |
| B — new AnimationCreationSession replacing/wrapping old | Cleaner generic naming and future expansion | High migration surface, duplicate owner/wrapper lifetimes or wholesale test/import churn; no current missing Session responsibility justifies it | Reject for initial scope |
| C — route through existing conversion coordinator/session as-is | Reuses convertFrameSource/ConversionJob loop and ConversionSession validation | Current prepare rejects static sources, assumes one animated VirtualFile/source format; target same-as-source rule and target-change result revocation conflict with Creator. Synthetic GIF/VirtualFile would conceal assumptions; generalizing shared convert.ts also affects video callers | Do not adopt as-is; reuse its contracts/encoder/readback components in A |

A deliberately reuses the validated **target transport/Worker/encoder** while keeping
CreationSession's product ownership. A small static-specific broker can follow the
existing transfer/accepted/ACK loop without changing convert.ts or video callers.
This bounded wrapper duplication is preferable to broad coordinator generalization
during initial integration; parity/contract tests must guard it. Later common-loop
extraction is a separate decision, not automatic M10A2 cleanup.

Source preparation routines may be narrowly extracted from encoder-core.ts into a
vendor-free helper reused by the legacy core and new source Worker. That is source
preparation reuse, **not merging the two GIF encoder wrappers** or rewriting codecs.
Keep legacy GIF service/core/Worker as historical regression references until the
new product path passes; do not delete them or mass-rename CreateGif.

Proposed flow (names planned; existing reusable names retained):

```text
CreationSession: ordered sources + captured settings/target
 → StaticAnimationEncoder (new small job/broker boundary)
 → StaticImageSequenceSource implements AnimationFrameSource (new client)
 ↔ static-source.worker: existing-style sequential scan / native decode / canvas
 → CanonicalAnimationFrame transferred through main
 → existing EncoderWorkerClient → existing conversion/encoder.worker.ts
 → selected GIFAnimationEncoder | WebPAnimationEncoder | APNGAnimationEncoder
 → source/encoder teardown → exact-range Blob
 → BinaryFormatDetector + inspectConversionOutput/openAnimationFrameSource
 → validated CreationResult + one URL
 → same Viewer Preview / fresh target-correct Download
```

No GIF intermediate exists for WebP/APNG. The full file-level scope, ordered
implementation gates, test matrix, Android plan and stop conditions are in the
[implementation plan](../planning/m10a2-animation-creator-implementation-plan.md).
