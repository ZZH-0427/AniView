## Native gate NATIVE-SECURITY-01

The following assessment is the original pre-remediation checkpoint. The current
S2 resolution is recorded after it; UNKNOWN here remains a historical finding.

**CONFIRMED facts**:

- The frozen component is 7-Zip26.05, source
  `b88c6bc09339de32f7d18bbab900686b244f42ba`, compiled with Emscripten 6.0.13.
- [Official history](https://www.7-zip.org/history.txt) dates 26.06 to 2026-11-06;
  the [official release](https://github.com/ip7z/7zip/releases/tag/26.06) was
  published on November7 and includes bug/vulnerability fixes.
- The [official source comparison](https://github.com/ip7z/7zip/compare/b88c6bc09339de32f7d18bbab900686b244f42ba...26.06)
  changes `CPP/7zip/Compress/Rar3Decoder.{cpp,h}` and
  `CPP/7zip/Common/InBuffer.cpp`, including error/exception-state handling.
- The actual frozen build recipe includes `Rar3Decoder.o` and `InBuffer.o`.
  The RAR handler selects this decoder family for supported RAR4 unpack versions;
  these are not excluded merely by rejecting other archive container formats.

**UNKNOWN**: the effect of the newly identified failure path on this exact
WebAssembly build, its publication/error behavior and recovery. No new adversarial
archive execution completed during this audit. Further sample validation was
stopped by an automatic safety check; it was not retried through an alternative
execution path. No browser crash, disclosure, exploitability or new product failure
is claimed from the source comparison alone.

**Decision**: retain a release gate until an independently reviewed assessment or
minimal remediation establishes the effect on the supported compiled path. The
64MiB linear-memory maximum, Worker boundary and ordinary/negative regression
passes are real safeguards, but do not by themselves resolve a newly identified
native error-state question. Likewise, the npm production audit does not cover
this separately built native component. This is more specific than blocking only
because a newer version exists.

Minimum next work is a separately reviewed native security assessment/remediation:
evaluate the relevant official fixes or a bounded-component upstream update,
preserving the RAR4 NUL/Unicode patch, ABI and all safety limits. If native inputs
change, generate new JS/WASM hashes, source package, notices and manifest, rerun
filename/compatibility/boundary/cancel/privacy regressions, then freeze a new
candidate before Android acceptance. This document does not authorize or perform
that work, and does not silently replace frozen26.05 with26.06.

## Existing runtime security checks

upload endpoint or telemetry, same-origin Worker/WASM imports, no runtime CDN,
session-local archive credentials, no tested password in URL/storage/network
records, path/special-entry rejection, bounded selected output, timeout/terminate
and cancel/replacement isolation. Request assertions permit only GET/HEAD plus
