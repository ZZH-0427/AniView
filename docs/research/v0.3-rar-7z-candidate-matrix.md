# M10C1 — RAR/7z candidate and evidence matrix

Research date: 2026-11-05. No production dependency installation or integration.
Main audit: [feasibility and architecture](v0.3-rar-7z-feasibility-audit.md).
`T` = measured in this audit; `S` = source/documented capability, not a phone or
complete-format test; `U` = unverified. A package name is not an engine version.

currently names unrarsrc-7.3.2.tar.gz. Do not call the beta a stable release.

| @unrar-browser/core 1.0.3 | S | S | no | UnRAR S | API/build encryption enabled S | no | MEMFS full input + output | public loader misdetects Worker as Node; adapter required |

The two libarchive comparison rows do not imply current upstream supports the
same exact codec set as these older binaries. Current source still rejects 7z
AES and encrypted RAR. Detection of encryption is not decryption support.

Codec tests: sevenzip-wasm passes native-oracle hashes for COPY, LZMA, LZMA2,
Deflate, BZip2, PPMd, BCJ+LZMA2, BCJ2+LZMA2, Delta+LZMA2. libarchive-wasm passes
the same nine *first ASCII entry* probes; its later Unicode pathname test fails.
These small filters fixtures confirm build inclusion, not every architecture,
filter combination or hostile method graph. Full compatibility is not promised.

| Candidate/path | Input copies | Observable WASM high-water | Output ownership | Cancel |

Binary memory sections: sevenzip/7z-wasm initial 17039360, maximum 2147483648
bytes, nonshared wasm32, memory defined in module rather than a replaceable import.
libarchive-wasm and dedicated UnRAR builds likewise allow 2 GiB; this is an address
ceiling, not an Android-safe operating budget. No full OS/GPU/RSS peak is claimed.

Evidence under ignored `.tools/m10c1/`: registry/package integrity and provenance
summaries, asset hashes, binary/static scans, native extraction oracles,
`desktop.json`, `followup-desktop.json`, `volume-results.json`, `rar4-solid.json`
and `phone-access.json`. Pinned source references identify downloaded files;
temporary source/binary/browser-profile/build caches are cleaned after testing.
Fresh Android summaries are archived in the main audit. No third-party
source/binary or generated fixture is committed.
