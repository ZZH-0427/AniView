# M10C2 — bounded memory and workload evidence

2026-11-05. **Desktop complete; initial bounded-build Android RAR4 failure under investigation.**
These are experimental mechanisms/values, not approved production limits.
Reference: sevenzip-wasm 26.5.0 / 7-Zip 26.05. Actual binary is a custom source
build, not a binary maximum patched after compilation.

## Enforced boundaries

Compiled memory section: one nonshared wasm32 memory, initial256 pages
(16,777,216 bytes), maximum1024 pages (67,108,864 bytes), growth enabled.
Emscripten6.0.13, exceptions enabled, ABORTING_MALLOC=0. The engine cannot use a
larger linear memory by bypassing a JS observer. No observer hook is the guard.
This ceiling does not cap JS heaps, Blob backing, browser/compiler/native memory,
Worker infrastructure or OS RSS. It is not a promise of a 64 MiB tab footprint.

Experimental coordinator/adapter limits: input32 MiB; actual selected output8 MiB;
entries1000; one path1024 chars; cumulative path128 Ki chars; recognized dictionary8
MiB; cumulative source reads128 MiB; external deadline15 s. Do not inherit ZIP's
512 MiB allowance. Caller can lower these test values, not silently raise them.

File/Blob mounts use WORKERFS; header signature reads8 bytes. No explicit whole
archive ArrayBuffer or archive-sized MEMFS input is created. Observed maximum
FileReaderSync range is1 MiB. Native stdio/decoder copies still exist. Selected
output uses a capped native vector in WASM, not an output pathname or MEMFS tree.
Declared known size is checked before reserve. Unknown size uses the actual
pre-write limit. Transfer makes one JS copy from heap, then frees native output
before postMessage transfer. Caller Blob construction would be a separate future
ownership step; this experiment returns ArrayBuffer and creates no media URLs.

## Before-allocation distinction

Common LZMA/LZMA2 and RAR method metadata can reveal dictionary information
before *selected extraction*. For instance LZMA2:22 maps to4 MiB and
v6:m5:128K maps to128 KiB. This is validated, bounded method metadata, not a
complete universal coder-graph memory estimate. Unknown remains null. RAR4 often
does not expose a reliable dictionary estimate. Multiple coder/filter graphs,
crypto/state/output and allocator overhead cannot be collapsed into that number.

**7z/RAR universal metadata-before-allocation guarantee: NO.** Opening compressed
or encrypted headers can allocate before product metadata exists. This is now
bounded by the compiled64 MiB maximum and controlled failure; it is not a
claim that the metadata guard always runs first. Product policy must keep this
fallback and treat allocation failure as fatal to that dedicated archive instance.

Fault injection skips declared-size/dictionary preflight while retaining native
actual-output and WASM limits. Oversized dictionary returns RESOURCE_LIMIT with
zero retained output; medium random output also stops before crossing1 KiB and
discards partial output. These probe methods are not production API candidates.

## Solid work and deadline

For the6 MiB solid archive, first/middle/last sequential extraction cumulative
source reads are3145912 / 8388792 / 14680639 bytes. Incremental reads therefore
are3145912 / 5242880 / 6291847, with2 MiB selected output each. These counts include
rereads and are not exact decompressed work. RAR4/RAR5 solid first/middle/last hashes
also match. Unknown total solid work cannot be precisely preflighted.

The source-I/O budget bounds observed reads, not decompressed CPU steps. The
external deadline is the separate wall-clock fallback, terminating the Worker.
Test deadline1 ms produces ARCHIVE_TIMEOUT. Cancel5 times → fresh reopen → different
entry success; open/list/extract/close10 times and close during open also pass.
Generation/request IDs reject late old-instance responses in a separate unit test.

Close removes application ownership of the Worker and thus its WASM/mount/native
output graph. Created=terminated is resource lifecycle balance, not proof that the
OS immediately returned every byte. No heap shrink or measured system RSS claim.
